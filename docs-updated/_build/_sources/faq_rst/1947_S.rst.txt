Dynamic Creation and Management of APCount Vectors
===================================================

When recording spike times at multiple locations (e.g., soma and nodes) in NEURON models, dynamically creating uniquely named vectors is not necessary and can be cumbersome.

Instead of generating variable names like ``timevec1``, ``timevec2``, ... dynamically, use an array of objrefs:

.. code-block:: hoc

    const NNODES = 20
    create node[NNODES]
    objref apc_nodes[NNODES], timevec[NNODES]

    for j=0, NNODES-1 node[j] {
        apc_nodes[j] = new APCount(0.5)
        timevec[j] = new Vector()
        apc_nodes[j].record(timevec[j])
    }

This idiom scales well and simplifies data management, avoiding "access abuse" by using proper looping constructs such as:

.. code-block:: hoc

    for j=0, NNODES-1 node[j] {
        ...
    }

For greater flexibility, prefer using the :class:`List` to hold :class:`APCount` objrefs, especially when the number of sections or recording sites is not fixed:

.. code-block:: hoc

    objref apclist, tobj
    apclist = new List()

    forall for (x,0) {
        tobj = new APCount(x)
        apclist.append(tobj)
    }
    tobj = nil  // remove temporary reference

Using :class:`List` allows dynamic resizing and easy access to all APCount objects via :meth:`List.count` and :meth:`List.o`.

.. note::

   Avoid embedding “magic numbers” by defining symbolic constants (e.g., ``NNODES``) and use array or list constructs for better scalability and maintainability.
