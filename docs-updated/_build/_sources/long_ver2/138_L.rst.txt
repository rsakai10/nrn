Stopping a Simulation After a Preset Number of Spikes
======================================================

When running long or large sets of simulations with varying spike counts, it is often desirable to stop the simulation after a preset number of spikes have occurred instead of running until a fixed time :attr:`tstop`. NEURON provides an efficient way to achieve this without excessive overhead from checking spike counts every time step.

Using the Event Delivery System with :class:`NetCon`
-----------------------------------------------------

The :meth:`NetCon.record` method not only records spike times into a :class:`Vector`, but can also be used to call a procedure on each detected spike event. This allows custom handling such as counting spikes and terminating the simulation once a target number has been reached.

HOC Example:

.. code-block:: hoc

    objref nc, stv
    stv = new Vector()
    // Replace 'source' with the appropriate spiking source (e.g. a Section or ArtificialCell)
    nc = new NetCon(source, nil)

    const int MAXNUM = 3
    // Procedure to handle and count spikes
    proc counter() {
      stv.append(t)      // Record spike time
      if (stv.size() == MAXNUM) {
        stoprun = 1      // Flag to stop simulation
      }
    }
    // Attach counter procedure to NetCon spike events
    nc.record("counter()")

Preventing Residual Data Between Runs
-------------------------------------

Since `nc.record()` with a procedure argument does not clear the spike times vector automatically on simulation reinitialization, it is important to reset the :class:`Vector` before each run. Use an :class:`FInitializeHandler` to clear `stv` at the start of every simulation run:

.. code-block:: hoc

    proc reset_stv() {
      stv = new Vector()
    }

    objref fih
    fih = new FInitializeHandler("reset_stv()")  // clears stv before run starts

Allowing Time for Event Delivery and Target Effects
---------------------------------------------------

Because spike source events can have propagational delays and targets may require some time to respond, the simulation should not be halted immediately when the spike count is reached. Instead, schedule the simulation to stop after a waiting period using the :meth:`CVode.event` method:

.. code-block:: hoc

    const double WAIT = 8   // ms to wait after last spike to allow event propagation

    proc counter() {
      stv.append(t)
      if (stv.size() == MAXNUM) {
        cvode.event(t + WAIT, "stoprun = 1")
      }
    }

Notes:

- The global :class:`CVode` instance is automatically created when running standard simulations (e.g., via :func:`load_file("nrngui.hoc")`).
- If spikes occur more frequently than WAIT minus synaptic delay, overlapping events could occur; adjust WAIT accordingly.

Displaying Spike Times and Stopping the Simulation
--------------------------------------------------

To automatically print the spike times after the final spike and then stop the simulation, modify the counter to schedule a wrap-up procedure:

.. code-block:: hoc

    proc wrapup() {
      print "spike times:"
      stv.printf()
      stoprun = 1
    }

    proc counter() {
      stv.append(t)
      if (stv.size() == MAXNUM) {
        cvode.event(t + WAIT, "wrapup()")
      }
    }

Python Equivalent
----------------

With the NEURON Python interface, the same logic applies using callbacks and event scheduling:

.. code-block:: python

    from neuron import h

    MAXNUM = 3
    WAIT = 8  # ms

    stv = h.Vector()
    nc = h.NetCon(source, None)  # replace source with your spike source object

    def wrapup():
        print("spike times:")
        print(list(stv))
        h.stoprun = 1

    def counter():
        stv.append(h.t)
        if stv.size() == MAXNUM:
            h.cvode.event(h.t + WAIT, wrapup)

    nc.record(counter)

    def reset_stv():
        global stv
        stv = h.Vector()

    # Register initialization callback to reset spike vector before each run
    fih = h.FInitializeHandler(1, reset_stv)

.. note::

    The :meth:`NetCon.record` method can accept either a :class:`Vector` or a string naming a procedure to call on each spike event.

Summary
-------

- Use :class:`NetCon.record` with a callback to count spikes efficiently without timestep polling.
- Reset data vectors before each run with :class:`FInitializeHandler` to avoid data from previous runs.
- Use :meth:`CVode.event` to delay stopping the simulation after the last spike to allow event propagation.
- Print spike times after simulation ends within the scheduled callback, if desired.

This approach provides a clean, efficient, and event-driven method to stop simulations once a target number of spikes have been generated.
