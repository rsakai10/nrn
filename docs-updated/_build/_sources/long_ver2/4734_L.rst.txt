Factors Influencing NEURON Simulation Run Time Beyond Total Compartment Count
================================================================================

When comparing simulation run times between models differing in morphology and segmentation, it is important to consider factors beyond just the total number of compartments (segments). The following points clarify the main influences on NEURON simulation performance:

Complexity Measured by Total Number of ODEs
-------------------------------------------

Each segment in a NEURON model typically involves solving one ordinary differential equation (ODE) for the cable equation. However, additional ODEs arise from mechanisms and processes associated with the segment:

- **Distributed mechanisms** (e.g., ion channel density mechanisms specified with the `SUFFIX` keyword in NMODL) add one or more state variables, each requiring integration.
- **Certain point processes** (e.g., `ExpSyn` with 1 ODE, `Exp2Syn` with 2 ODEs).
- **Extracellular mechanisms** add two ODEs per segment if NEURON is compiled with `nlayer == 2`.
- **Reaction-diffusion (rxd) mechanisms** add ODEs for each rxd compartment state variable that requires numerical integration.

Hence, total runtime correlates better with the number of ODEs solved rather than the total compartment count alone.

Cache Efficiency and Memory Organization
---------------------------------------

Simulation speed can also be affected by how efficiently the model data fits into CPU cache and how NEURON organizes computations in memory:

- A simpler model with fewer segments and simpler morphology may require less cache swapping, increasing efficiency.
- More complex, branched morphologies may scatter memory accesses, causing more cache misses and slower simulation.
- Enabling `cache_efficient` mode in variable time step integration can improve performance by optimizing memory access patterns.

Using `cache_efficient` Mode
----------------------------

To enable cache efficient integration with variable time step methods, set the `cache_efficient` attribute of the CVode solver:

**Python:**

.. code-block:: python

    from neuron import h
    cvode = h.CVode()
    cvode.cache_efficient(1)  # Enable cache efficient mode

**HOC:**

.. code-block:: hoc

    objref cvode
    cvode = new CVode()
    cvode.cache_efficient(1)  // Enable cache efficient mode

This mode attempts to reorder memory accesses during integration to improve CPU cache usage, potentially reducing simulation run times on complex models.

Summary
-------

- Total simulation time depends primarily on the total number of ODEs solved, not just the number of compartments.
- Morphological complexity indirectly affects runtime by increasing ODE count and affecting memory access patterns.
- Enabling `cache_efficient` mode in :class:`CVode` may improve simulation performance for complex models.
