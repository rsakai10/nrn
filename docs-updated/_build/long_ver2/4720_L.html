Reading Ionic Currents from NMODL Mechanisms in HOC or Python

This section explains how to access ionic current variables implemented in NMODL mechanisms when using the NEURON simulator, focusing on how to properly read currents through point processes and density mechanisms from HOC or Python. It addresses common difficulties when dealing with nonspecific currents, multiple ions, and synaptic point processes distributed arbitrarily on a neuron model.

Background

NMODL mechanisms can implement ionic currents either as density mechanisms (currents per unit membrane area, e.g., mA/cm²) or as point processes (currents in absolute units, e.g., nA). Ionic currents declared using :paramref:`USEION` statements allow NEURON to track currents for standard ions (na, k, ca, etc.), making it easier to record total ionic currents in each segment.

Challenges arise when:

  • Mechanisms use nonspecific currents instead of standard ion currents.

  • Synaptic point processes contribute ionic currents that are difficult to access by iterating over segments because synapses are arbitrarily distributed.

  • Current variables are implemented in range or assigned blocks with confusing units or are calculated inside point processes.

Recommendations and Best Practices

  1. Use `USEION` Statements to Declare Ionic Currents

    Replace NONSPECIFIC_CURRENT declarations in your MOD files with appropriate USEION statements. This lets NEURON handle the ionic currents automatically, accumulating currents of a given ion across all mechanisms in a segment.

    Example:

    ```neuron NEURON {

    USEION na READ ena WRITE ina VALENCE 1 USEION k READ ek WRITE ik VALENCE 1 …

    This creates segment-specific ionic currents ina(x), ik(x) accessible from HOC or Python, with units mA/cm².

  2. Create New Ionic Species for Synaptic Point Processes

    If current is generated by synaptic point processes and you need to separate synaptic sodium or potassium currents from other sources, declare new ionic species with a VALENCE clause, for example:

    ```neuron NEURON {

    USEION nas WRITE inas VALENCE 1 USEION ks WRITE iks VALENCE 1

    This automatically tracks synaptic sodium (inas) and potassium (iks) currents for each segment.

  3. Units Consistency

    • Density mechanisms use currents in mA/cm².

    • Point processes use currents in absolute units such as nA.

    • The permeability parameter Pmax in density mechanisms (e.g., in cm/s) differs in meaning and units compared to point process implementations (e.g., m³/s or volume/time).

    Ensure units in your MOD files are consistent with the biological interpretation and NEURON’s requirements.

  4. Accessing Ionic Currents in HOC or Python

    When USEION is properly declared, ionic currents for a segment x are accessible as functions named by the ionic variable, e.g.:

    `hoc ina(x)   // sodium current density (mA/cm2) at segment x inas(x)  // synaptic sodium current density (mA/cm2) at segment x (for custom ionic species) `

    Since these are densities, to get absolute current (in nA) use the segment area:

    `hoc absolute_current_na = ina(x) * area(x) / 100  // area in um², factor converts mA/cm2 to nA `

  5. Summing Currents Over Entire Cell

    Here is a sample HOC function to compute the total current for a custom ion nas over all segments:

    ```hoc func inas_total() { local tmp

    tmp = 0 forall for (x, 0) {

    tmp += inas(x) * area(x) / 100

    } return tmp

  6. Avoid Iterating Over Point Process Arrays to Access Current Variables

    Point processes placed on the morphology do not expose ionic current variables as arrays accessible from HOC. Attempting to access AMPAsyn[j].Pmax as an array without proper object referencing results in errors like:

    ` NEURON: AMPAsyn not an array variable `

    Instead, use ionic tracking with USEION as above, which captures the total ionic current irrespective of synapse number or location without the need to iterate over created point process instances.

Example: Modified AMPAR NMODL Code Excerpt

```neuron NEURON {

POINT_PROCESS ghkampa USEION nas WRITE inas VALENCE 1 USEION ks WRITE iks VALENCE 1

RANGE taur, taud RANGE iampa, inas, iks RANGE P, Pmax

}

ASSIGNED {

inas (nA) iks (nA) v (mV) P (cm/s) factor iampa (nA) Area (cm2)

}

BREAKPOINT {

SOLVE state METHOD cnexp P = B - A

inas = P * ghk(v, nai, nao, 1) * Area iks = P * ghk(v, ki, ko, 1) * Area iampa = inas + iks

}

Accessing Synaptic Sodium Current in HOC

```hoc proc read_compartment_current() {

if (ismembrane(“nas_ion”)) {

ina_syn = inas($1) * area($1) / 100 // Convert from mA/cm2 to nA

}

}

Key Notes

  • Declaring new ions like nas and ks requires a VALENCE clause.

  • Variables declared with USEION … WRITE are automatically created per segment and accessible in HOC/Python.

  • To record currents, make sure to attach all synapses before creating Vector recordings or making calls.

  • The current accessed with inas(x), ina(x) etc., are densities (mA/cm²); multiply by segment area and divide by 100 to convert to nA.

  • Ensure your MOD files reflect proper units for parameters, notably permeability, to maintain biophysical consistency.

Summary

To read ionic current variables implemented in NMODL from HOC or Python, use USEION statements to define ionic currents in the MOD files with appropriate ion names and VALENCE for custom ions associated to synaptic point processes. This avoids the complexity and unreliability of iterating over synapse instances by having NEURON accumulate the currents per segment automatically. Then access those currents as density functions per segment, and multiply by segment area for absolute currents.

This approach simplifies recording, analysis, and ensures correct biophysical unit handling in your NEURON models.
