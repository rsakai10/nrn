Warning

When using a custom initialization procedure that calls fadvance() multiple times to advance the model before starting a simulation, it is essential to call frecord_init() afterward (or call finitialize(), which calls frecord_init() internally).

This is necessary because Vector.record() objects maintain an internal index incremented on each fadvance(). Without resetting this index via frecord_init(), recorded vectors will be shifted, causing delays or misalignment in recorded synaptic or voltage signals.

proc init() {
    ; ... setup code ...
    for i=0,19 {
      fadvance()
    }
    frecord_init()  // must reset recording vector indices
    ; ... continue initialization ...
}

def init():
    for _ in range(20):
        h.fadvance()
    h.frecord_init()  # reset recorded vectors indices

Note

Calling finitialize() after advancing time implicitly calls frecord_init(). Models that include calls to finitialize() after fadvance() calls do not experience this problem.
